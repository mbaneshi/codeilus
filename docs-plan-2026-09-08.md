# Codeilus — Master Plan

> **One command. Any codebase. A complete learning experience.**

---

## 1. Purpose & Vision

AI coding tools have made developers 100x more productive — but not 100x more knowledgeable. Engineers ship code into codebases they don't deeply understand. Onboarding takes weeks. Tribal knowledge lives in people's heads. Documentation rots.

**Codeilus fixes this.** It's a single Rust binary that analyzes any codebase and transforms it into a structured, gamified, interactive learning experience in the browser.

```
codeilus ./any-repo → browser opens → start learning
```

**The core thesis:** Static analysis + knowledge graphs + LLM narration + gamification = the fastest way for a human to truly understand a codebase.

### What Codeilus Is NOT
- Not a linter or CI tool
- Not a documentation generator (though it generates docs as a side effect)
- Not an IDE plugin
- Not an AI coding assistant

### What Codeilus IS
- A **codebase learning platform** — like Duolingo for codebases
- A **knowledge extraction engine** — turns code into a navigable graph
- A **single binary** — no Docker, no cloud, no API keys required (Claude Code optional for LLM features)

## 2. Target Users & Use Cases

### Primary Users

| User | Pain Point | How Codeilus Helps |
|------|-----------|-------------------|
| **New team member** | Onboarding takes 2-4 weeks, reading random files | Structured curriculum: Chapter 1 → Chapter N, guided reading order |
| **Senior engineer** | Inherited a legacy codebase, needs mental model fast | Architecture diagram + community graph + metrics heatmap in 60 seconds |
| **Tech lead** | "What breaks if we remove this?" | Blast radius analysis, impact scoring, what-if simulation |
| **Open source contributor** | Wants to contribute but doesn't know where to start | Learning path identifies entry points, suggests extension points |
| **Code reviewer** | Reviewing a PR in unfamiliar code | Q&A: "how does authentication work here?" with code references |

### Core Use Cases

1. **Learn a codebase end-to-end** — Follow a structured curriculum with chapters, quizzes, XP, and progress tracking
2. **Explore interactively** — Navigate the knowledge graph, drill into communities, trace execution flows
3. **Understand architecture** — Auto-generated diagrams, function flowcharts, dependency trees
4. **Assess code health** — Metrics heatmap, anti-pattern detection, complexity hotspots
5. **Ask questions** — Natural language Q&A powered by Claude Code with full graph context
6. **Measure impact** — "If I change X, what breaks?" with depth-scored blast radius
7. **Export & share** — Generate a static HTML learning site for the team

### Tech Stack

| Layer | Technology | Why |
|-------|-----------|-----|
| Language | Rust | Performance, single binary, memory safety |
| Async | Tokio | HTTP, WebSocket, Claude CLI streaming |
| CPU parallelism | Rayon | Tree-sitter parsing is CPU-bound |
| HTTP | Axum | Lightweight, tower middleware ecosystem |
| Database | SQLite (WAL mode) | Zero config, embedded, concurrent reads |
| Graph algorithms | petgraph | In-memory for Louvain, BFS, cycle detection |
| Parsing | tree-sitter | Multi-language AST extraction |
| Frontend | SvelteKit 5 + TailwindCSS 4 | Compiled to static, embedded via rust-embed |
| LLM | Claude Code CLI (subprocess) | Zero API keys, streaming JSON output |
| MCP | rmcp (stdio) | AI agent integration |

## 7. Core Modules — Deep Dive

### 7.1 codeilus-parse (Sprint 1)

**Purpose:** Extract every symbol from every file in any codebase.

**Input:** Directory path
**Output:** `Vec<ParsedFile>` with symbols, imports, calls, heritage

| Capability | Detail |
|-----------|--------|
| Languages | Python, TypeScript, JavaScript, Rust, Go, Java (+ 6 more planned) |
| Parser | tree-sitter with per-language query strings |
| Parallelism | rayon work-stealing, 20MB byte budget chunking |
| Ignore | `.gitignore` via `ignore` crate |
| Import resolution | tsconfig paths, Python relative, Go modules, Rust mod/use |

**Key types:**
```rust
struct ParsedFile {
    path: PathBuf,
    language: Language,
    symbols: Vec<Symbol>,     // functions, classes, structs, traits, interfaces
    imports: Vec<Import>,     // resolved cross-file references
    calls: Vec<Call>,         // function/method invocations
    heritage: Vec<Heritage>,  // extends, implements
}
```

**Port from:** GitNexus `src/core/ingestion/` — chunked parsing, symbol extraction, import resolution

---

### 7.2 codeilus-graph (Sprint 2)

**Purpose:** Build a knowledge graph of how code connects.

**Input:** `Vec<ParsedFile>` + SQLite data
**Output:** Edges, communities, execution flows stored in DB

| Capability | Detail |
|-----------|--------|
| Edge types | CALLS, IMPORTS, EXTENDS, IMPLEMENTS, CONTAINS |
| Confidence | 0.0–1.0 scoring on each edge |
| Community detection | Louvain algorithm on petgraph |
| Process detection | Entry point identification → BFS through CALLS edges |
| Entry heuristics | main(), index, HTTP handlers, CLI commands |

**Port from:** GitNexus `src/core/ingestion/` (call tracing, communities), emerge `emerge/graph.py`

---

### 7.3 codeilus-metrics (Sprint 3)

**Purpose:** Quantify code health.

| Metric | Source |
|--------|--------|
| SLOC | Line counting per file |
| Fan-in / Fan-out | Edge count per symbol |
| Cyclomatic complexity | Estimate from AST branching |
| Modularity score | Louvain modularity value |
| TF-IDF keywords | Per community, for naming/description |
| Git churn | `git2-rs` — commit count per file |
| Contributors | `git2-rs` — unique authors per file |
| Heatmap score | Composite of complexity × churn × fan-out |

**Port from:** emerge `emerge/metrics/`

---

### 7.4 codeilus-analyze (Sprint 3)

**Purpose:** Detect problems and suggest improvements.

| Detection | Method |
|----------|--------|
| God class | Methods > threshold + high fan-out |
| Long method | Line count > threshold |
| Circular dependencies | DFS cycle detection in petgraph |
| Security hotspots | Keyword heuristics (eval, exec, sql, password) |
| Test gaps | Files with no test file counterpart |
| Refactoring candidates | High complexity + high churn |

**Port from:** GitVizz `gitvizz/graph_search_tool.py`

---

### 7.5 codeilus-diagram (Sprint 4)

**Purpose:** Auto-generate visual diagrams.

| Diagram | Method |
|---------|--------|
| Architecture | Communities → Mermaid subgraphs with inter-community edges |
| Function flowchart | AST → FlowchartIR (Entry, Exit, Decision, Process, Loop, Exception) → Mermaid |
| File tree | ASCII rendering, 4 styles (classic, slashed, minimal, compact) |
| LLM-enhanced | 3-stage pipeline: analyze → generate → validate/fix (up to 3 attempts) |

**Port from:** CodeVisualizer (FlowchartIR), gitdiagram (LLM pipeline), GitHubTree (ASCII tree)

---

### 7.6 codeilus-learn (Sprint 6) — THE DIFFERENTIATOR

**Purpose:** Transform analysis data into a gamified curriculum.

**Curriculum generation:**
1. Topological sort communities by dependency
2. Entry-point communities first, core before features (by fan-in)
3. Each community → one chapter
4. Special: "Chapter 0: The Big Picture" and "Final: Putting It All Together"
5. Within chapters: files ordered by dependency (imported before importing)

**Chapter structure:**
- Title + overview (LLM-generated or TF-IDF summary)
- Key concepts (TF-IDF keywords + descriptions)
- Interactive diagram (community subgraph)
- Code walkthrough (guided reading order with annotations)
- Connections to other chapters
- Quiz/challenge
- Difficulty rating (from complexity metrics)

**Gamification:**

| Action | XP |
|--------|-----|
| Complete a section | +10 |
| Complete a chapter | +50 |
| Pass a quiz | +25 |
| Explore graph | +5 |
| Ask a question | +5 |

**Badges:** First Steps, Chapter Champion, Graph Explorer, Quiz Master, Deep Diver, Completionist, Polyglot, Code Detective

**Quiz types:**
- Multiple choice from graph: "Which module calls `authenticate()`?"
- True/false from metrics: "`utils.py` has more than 10 functions"
- Impact questions: "If you removed `UserService`, what breaks?"
- Free-form validated by Claude Code
- Adaptive difficulty based on past performance

---

### 7.7 codeilus-llm (Sprint 5)

**Purpose:** Claude Code powers narration, Q&A, translation.

**Mechanism:** Spawn `claude --output-format stream-json --print` as subprocess. Parse streaming JSON. Cache results in `narratives` table.

**Capabilities:**
- Architecture narrative generation
- Module/function explanations
- Natural language Q&A with graph context
- Code translation (explain in Spanish, etc.)
- Refactoring suggestions
- Quiz answer validation

**Graceful degradation:** If Claude Code is not installed, all non-LLM features work perfectly. LLM features show: "Install Claude Code to unlock Q&A, explanations, and translation."

**Port from:** forge-project `crates/forge-process/` (subprocess spawning + stream parsing)

---

### 7.8 codeilus-search (Sprint 7)

**Purpose:** Find anything, assess impact.

| Feature | Method |
|---------|--------|
| Full-text search | SQLite FTS5 virtual tables |
| Ranking | BM25 + RRF (Reciprocal Rank Fusion) |
| Blast radius | Reverse BFS on edges from target symbol |
| Impact scoring | d=1 WILL BREAK, d=2 LIKELY, d=3 MAY |
| What-if removal | Simulate removing a symbol, report all affected processes |

**Port from:** GitNexus `src/core/search/` (BM25, RRF), MCP tools (impact analysis)

## 12. Key Technical Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Graph storage | SQLite tables + petgraph in-memory | Single dep, proven. petgraph only for CPU-heavy algorithms |
| Community detection | Louvain (not Leiden) | Simpler to implement in Rust, adequate for learning use case |
| CPU parallelism | rayon (not tokio) | Tree-sitter parsing is CPU-bound; rayon's work-stealing is ideal |
| Async I/O | tokio | HTTP server, WebSocket, Claude CLI streaming |
| LLM interface | Claude Code CLI subprocess | Zero API keys, forge-process pattern proven, streaming JSON |
| Frontend embed | rust-embed at compile time | Single binary distribution, no Node.js runtime needed |
| IDs | i64 (SQLite rowid) not UUID | Graph-heavy workload, i64 is faster for joins and lookups |
| Search | SQLite FTS5 (not tantivy) | Zero additional deps, good enough for codebase-scale text |
| Frontend | SvelteKit 5 + adapter-static | Compiles to static files, small bundle, reactive by default |

### Key Architectural Insight

**PocketFlow is pure-LLM with zero static analysis** — it guesses abstractions from raw code. **Codeilus has rich static analysis but weaker narrative generation.** The combination is more powerful than either alone:

```
PocketFlow approach:  raw code ──LLM──► abstractions ──LLM──► chapters
Codeilus approach:    raw code ──tree-sitter──► graph ──topo-sort──► chapters
Combined approach:    raw code ──tree-sitter──► graph ──LLM(with graph context)──► chapters
                                                  ↑
                                    communities, metrics, edges,
                                    entry points, confidence scores
                                    = structured context for better prompts
```

The LLM doesn't have to *guess* what the abstractions are — we *tell it* based on real data, and ask it to *explain and name* them for a human learner.
